# SMWR WAS 배치 명세서

문서 기준: 저장소 `SMWR_WAS` (Spring Boot, Quartz, Spring Batch). 운영에서 실제 `bat_id`·크론·`use_yn`은 DB `sys_batch_config` 가 단일 출처이며, 아래 표시명·클래스는 코드 기준이다.

---

## 1. 개요

**RTA 전체 집계 파이프라인**(`RtaUnifiedPipelineAggJob`) 상세는 [`RTA_전체집계파이프라인_명세서.md`](./RTA_전체집계파이프라인_명세서.md) 를 참고한다.

| 구분 | 설명 |
|------|------|
| **스케줄러** | Quartz (`Scheduler`). 부팅 후 `ApplicationReadyEvent` 에서 DB 메타를 읽어 크론 트리거 등록 (`com.sysconf.config.BatchConfig`). |
| **메타 테이블** | `sys_batch_config` — 배치 정의(`job_class`, `cron_expr`, `use_yn` 등). PK는 `bat_id`(시퀀스). |
| **실행 이력** | `sys_batch_run_his` — `BaseBatchJob` 이 RUNNING → SUCCESS/FAIL 로 갱신. |
| **Job 베이스** | `com.smw.monster.batch.BaseBatchJob` — 로그 수집, Micrometer, 짧은 트랜잭션으로 이력만 먼저 커밋. |
| **크론 스위치** | `smw.batch.quartz.enabled` (`application.yml`). `false` 이면 **자동 크론 미등록**. 수동 실행 API는 Scheduler 빈이 있으면 동작 가능. |
| **관리 API** | `com.admin.batch.rest.BatchController` — `/api/v1/batch` (관리자 권한 `@RequireAdmin`). |

---

## 2. Quartz Job (`BaseBatchJob` 상속)

`job_class` 에 **FQCN** 으로 등록한다. 예: `com.smw.monster.batch.RtaUnifiedPipelineAggJob`.

| 표시명 (getBatchName) | Java 클래스 | 주요 처리 | 동시 실행 제한 |
|----------------------|-------------|-----------|----------------|
| RTA 전체 집계 파이프라인 | `RtaUnifiedPipelineAggJob` | ① raw 정규화 (`applyPendingArenaReplayRawFromDb`, LIMIT·max-batches) ② 시너지 pending 소진 ③(선택) SWEX→`user_monster_owned_agg` ④(설정 시) 레거시 몬스터·티어 일별 ⑤ RTA 캐시 무효화 | `@DisallowConcurrentExecution` |
| RTA 티어 일별 집계 | `RtaTierDailyAggJob` | `rta_agg_tier_daily` 시즌별 재적재, 캐시 무효화 | `@DisallowConcurrentExecution` |
| RTA 랭크컷 스냅샷 집계 | `RtaRankCutSnapshotAggJob` | `rta_rank_cutoff_anchor_snap`, `rta_snapshot_rank_cut` 등, 캐시 무효화 | 없음 |
| RTA 고아 행 정리 | `ArenaRtaOrphanCleanupBatchJob` | `deleteArenaRtaOrphanChildrenGlobal` — `rta_match` 없는 unit/participant 정리 | `@DisallowConcurrentExecution` |

`sys_batch_config` 등록 예시: `sql/migrate_20260419_sys_batch_arena_rta_orphan_cleanup.sql` (삽입 후 운영에서 `use_yn`·`cron_expr` 조정).
| Swarfarm 몬스터 동기화 | `SwarfarmMonsterSyncJob` | Swarfarm API → 몬스터 데이터 | 없음 |
| Swarfarm 스킬 동기화 | `SwarfarmSkillSyncJob` | 스킬 데이터 | 없음 |
| Swarfarm 스킬 이펙트 동기화 | `SwarfarmSkillEffectSyncJob` | 스킬 이펙트 | 없음 |
| Swarfarm 리더 스킬 동기화 | `SwarfarmLeaderSkillSyncJob` | 리더 스킬 | 없음 |
| Swarfarm 던전 동기화 | `SwarfarmDungeonSyncJob` | 던전 | 없음 |
| Swarfarm 레벨 동기화 | `SwarfarmLevelSyncJob` | 레벨(웨이브) 정보 | 없음 |

**참고**

- 통합 파이프라인 주기·예시 `bat_id`는 주석에 **10001** 이 언급되나, 실제 PK는 DB 시퀀스다.
- 티어 일별 전용 등록 예시: `sql/migrate_add_rta_tier_daily_batch_config.sql` (저장소에 파일 있으면 참고).
- RTA 성능·인덱스·ANALYZE 메모: `sql/migrate_20260419_rta_batch_perf_index_analyze.sql`.

## 3. Spring Batch (Quartz와 별도)

설정 클래스: `com.smw.rta.batch.spring.RtaReplayPipelineJobConfig`.

| Job 이름 (상수) | 설명 |
|-----------------|------|
| `rtaReplayPipelineJob` | Step1: NDJSON 청크 → 정규화 적재. Step2: rid 청크 → `RtaSynergyAggService#applySynergyBatch`. |
| `rtaSynergyAggregateBatchJob` | 시너지 Step 만 단독 실행. |

- NDJSON 청크 기본: `DEFAULT_CHUNK = 1000`.
- 시너지 Step 청크 기본: `SYNERGY_DEFAULT_CHUNK = 50_000` (주석: jobParameters 로 조절 권장).
- 미집계: `rta_match.synergy_applied_at IS NULL`.

실행은 Spring Batch API / 스케줄 / 운영 스크립트에 따름(본 문서는 Quartz `sys_batch_config` 와 분리).

## 4. 주요 설정 (`application.yml` — `smw.rta`)

| prefix / 키 | 용도 |
|-------------|------|
| `smw.rta.raw-apply.*` | raw 정규화: `max-rows-per-run`, `max-batches-per-job`, `apply-chunk-size`, COPY/VALUES, `fail-fast-on-error` 등. |
| `smw.rta.batch.*` | 통합 Quartz Job: 시너지 배치/라운드/일시정지, 통합 내 스킵(레거시 몬스터·티어일별·보유몬 등). |
| `smw.rta.counter-agg.*` | 카운터 매치업 COPY 스테이징: `use-copy-staging`, `analyze-target-after-merge`, 청크 행 수 등. |
| `smw.rta.synergy-agg.*` | 시너지 집계 COPY 스테이징·레거시 UPSERT 임계. |
| `smw.rta.staging-merge.*` | 스테이징 merge 전 `ANALYZE staging`, `jit`, `work_mem`, 병렬 worker. |
| `smw.batch.quartz.enabled` | Quartz 크론 등록 여부. |

대량 백필 프로필: `application-bulkload.yml` 에 동일 네임스페이스 오버라이드.

## 5. 수동 실행·로그

- HTTP: `/api/v1/batch` 하위 (실행 시 `job_key` / `bat_id` 등 — `BatchController` 참고).
- 크론이 꺼져 있어도 Scheduler 가 있으면 수동 실행은 가능하다는 설명이 `application.yml` 주석에 있음.
- 수동 실행 시 SSE 스트림 ID 등은 `BaseBatchJob`·배치 컨트롤러 연동.

---

## 6. 신규 배치 추가 절차 (요약)

1. `BaseBatchJob` 을 상속하고 `executeBatch`, `getBatchName` 구현.
2. 필요 시 `@DisallowConcurrentExecution` 부여.
3. DB `sys_batch_config` 에 `job_class`(FQCN), `cron_expr`, `use_yn`, `bat_nm`, `sort_sn` 등 INSERT.
4. `smw.batch.quartz.enabled=true` 인 환경에서 애플리케이션 재기동 시 크론 등록 확인.
